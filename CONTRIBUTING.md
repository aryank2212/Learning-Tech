# Contributing to Learning-Tech

Thank you for wanting to help. Learning-Tech is open-source-leaning: you can ask for anything, and you can contribute anything that makes learning better.

## You can ask for anything
Open an issue for:
- a new subject, or a new topic inside a subject
- a tutorial you wish existed (or one that's broken)
- a practice set at a level you need
- a resource to add, or a correction to something wrong
- a question about any of the content

Good issues say what you're trying to learn, what you've already tried, and what would help.

## You can contribute
1. Fork the repository and create a branch.
2. Make your change. Keep it small and focused, so it's easy to review.
3. Check it: run the link check and read your Markdown on GitHub.
4. Open a pull request that says what changed and why.

Fixing a typo, a broken link or an unclear sentence is a valid contribution.

## Style rules
- Start each subject with the same four parts: install, syllabus, resources, practice (and a short "My personal take").
- Syllabus phases use checkboxes (`- [ ]`) and each phase ends with a project (🛠️).
- Mark resources with 🆓 (free) or 💲 (paid), and ⭐ for "start here".
- Link to official docs, well-known authors, and sources you have checked yourself. Don't add links to pirated copies.
- Never commit copyrighted books or papers. The `library/` folder is git-ignored for that reason; `scripts/fetch-library.sh` rebuilds it locally.
- Never commit keys, tokens, passwords or personal data.

## "My personal take" sections
These are opinions, and they're welcome as long as they're clearly the author's view. Keep them short, honest and useful. Disagreement is fine; say why.

## Code of conduct
Be kind, be specific, assume good faith. Critique ideas, not people. If something feels off, open an issue or contact the maintainer.
