# Tech Ethics

What technology should and shouldn't do, who it affects, and how engineers take responsibility for it. This is not a list of rules to memorise. It's a way of asking better questions before you ship.

Topics: privacy, fairness and bias, safety, surveillance, misinformation, labour, the environment, accessibility, open source and licensing, and professional codes of conduct.

## Prerequisites
None. It works best alongside [AI/ML](../../../ai/machine-learning/ai-ml/README.md) and [web development](../../../web/building/web-development/README.md), where the questions come up in real projects.

## How to study
- Read one case study a week. Then write a 300-word note: "What would I do differently, and why?"
- Apply the checklist in the syllabus (Phase 12) to every project you build.
- Discuss with other people. Ethics is clearer when you argue it out loud.
- Write down disagreements. Thoughtful people land in different places, and that's useful to know.

## Install
Nothing to install. Helpful tools:
- [uBlock Origin](https://github.com/gorhill/uBlock) — a browser extension that blocks trackers (install from your browser's extension store)
- [Fairlearn](https://fairlearn.org/) — fairness metrics in Python (`uv add fairlearn`)

## My personal take

*These are my own opinions, not a fixed syllabus. Disagree and make your own call.*

- Ethics isn't a box to tick at the end of a project. It's a set of questions you ask at the start, when they're cheap to answer.
- Read the case studies. Real failures teach more than principles do.
- Disagreement is normal here. The useful skill is making your reasoning clear enough that others can challenge it.
